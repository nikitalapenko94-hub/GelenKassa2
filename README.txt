GELEN LOUNGE — веб-прототип кассы

Файлы: index.html, manifest.json, sw.js, icon.svg.

Как запустить
1. Для быстрого просмотра можно открыть index.html в браузере.
2. Для установки как веб-приложения и работы офлайн разместите папку на статическом хостинге с HTTPS (например, GitHub Pages, Netlify или собственный сервер). Service Worker и установка PWA не работают при открытии через file://.
3. После первого открытия онлайн дождитесь загрузки приложения. Затем оно сможет открываться офлайн в том же браузере и на том же устройстве.

Синхронизация двух устройств (Supabase)
Данные по умолчанию хранятся локально. После настройки Supabase синхронизация запускается автоматически после изменений и при восстановлении интернета. Чтобы синхронизировать пару устройств, понадобится проект Supabase и интернет для первичной/последующей передачи. В Settings приложения → «Синхронизация двух устройств» укажите Project URL и anon/publishable key, затем создайте аккаунт либо войдите в один и тот же аккаунт на обоих телефонах. Держите сеть включённой для синхронизации; при офлайне записи остаются локальными и будут отправлены после восстановления сети. Повторный вход на втором устройстве загрузит общие данные.

Однократно настройте Supabase:
1. Включите Email/Password в Authentication → Providers; если подтверждение email включено, подтвердите адрес.
2. В SQL Editor выполните:

```sql
create table if not exists public.kassa_state (
  owner_id uuid primary key references auth.users(id) on delete cascade,
  payload jsonb not null,
  updated_at timestamptz not null default now()
);
alter table public.kassa_state enable row level security;
create policy "owner reads own kasa" on public.kassa_state
  for select to authenticated using (auth.uid() = owner_id);
create policy "owner inserts own kasa" on public.kassa_state
  for insert to authenticated with check (auth.uid() = owner_id);
create policy "owner updates own kasa" on public.kassa_state
  for update to authenticated using (auth.uid() = owner_id)
  with check (auth.uid() = owner_id);
grant select, insert, update on public.kassa_state to authenticated;
```
3. В приложении введите Supabase Project URL и anon/publishable key из Project Settings → API. Никогда не помещайте `service_role` key в браузер или публичный репозиторий.

Важно: это MVP-синхронизация, не система реального времени. Для синхронизации обоим устройствам нужны одинаковые URL и anon key; после первоначального входа каждое устройство запускает передачу при изменениях, восстановлении сети или вручную кнопкой. Продажи и смены объединяются по ID, остатки — по журналу движений, удаления помечаются. До первого объединения сделайте резервную копию на обоих устройствах. Одновременное редактирование одного товара может разрешиться в пользу последней версии. Для критичного денежного учёта нужна полноценная серверная система с транзакциями и аудитом.

Интерфейс адаптирован для телефонов и планшетов: горизонтальная прокрутка навигации, карточки и таблицы с мобильной прокруткой, увеличенные сенсорные поля и кнопки, компактная касса и модальные окна, учитывающие экранную клавиатуру и safe area.

В прототипе реализованы
- открытие смены с указанием начальной наличности;
- каталог товаров: создание, редактирование, удаление;
- чек с количеством товаров и оплатой наличными, картой, переводом или смешанным способом;
- расчёт сдачи;
- внесение и изъятие наличных; расходы с суммой, назначением (куда потрачены деньги), источником средств (касса или другой источник) и комментарием. Расход из внешнего источника не уменьшает остаток кассы;
- возвраты с привязкой к продаже, суммой, способом и причиной;
- закрытие смены с ожидаемым остатком, фактическим пересчётом и фиксацией расхождения;
- история операций и смен; CSV-экспорт операций включает проданные/возвращённые позиции и количество, а также для расходов — источник средств, назначение и комментарий; CSV-отчёт по сотрудникам включает количество проданных и возвращённых позиций по каждому товару;
- экспорт и импорт резервной копии JSON;
- локальное хранение и PWA-кэш для запуска офлайн;
- название заведения Gelen Lounge;
- PIN-доступ администратора: служебные разделы (история, смены, товары, склад, аналитика, настройки), создание и смена PIN;
- аналитика товаров: выручка после возвратов, количество единиц, чеки, средний чек, графики за 7/30 дней или всё время;
- склад: остатки товаров, сигнал низкого/нулевого остатка, поступления и списания с причиной и журналом движений;
- автоматическое списание товара при продаже и возврат на склад при указании возвращаемого количества; продажа сверх остатка блокируется;
- администратор добавляет/отключает сотрудников и задаёт личный PIN; сотрудник вводит своё имя и PIN, указывает начальную наличность при открытии смены;
- все чеки привязаны к сотруднику и его смене; администратор видит по каждому сотруднику число смен и чеков, продажи, возвраты, чистую выручку и средний чек; есть фильтр по сотруднику и периоду и экспорт отчёта сотрудников в CSV;
- отложенные чеки: сохранить корзину, задать/изменить название, сохранить комментарий и введённый способ оплаты, удалить или открыть снова. До завершения оплаты отложенный чек не списывает склад и не меняет кассу. Продолжить его может тот же сотрудник со своей открытой сменой; при нехватке текущего остатка приложение не даст загрузить чек.

Для уже существующих товаров первоначальный остаток будет 0. Внесите его через «Администратор → Склад → Поступление / списание».

Первый вход администратора
Нажмите «Вход администратора» и задайте PIN длиной 4–12 цифр. Для входа требуется HTTPS (Web Crypto); войдите заново после перезагрузки страницы. Для безопасности не используйте простые комбинации. Затем в «Администратор → Сотрудники» добавьте каждого сотрудника и задайте ему личный PIN. Для открытия смены персонал выбирает имя, вводит PIN и начальную наличность. Один браузер/касса поддерживает одну открытую смену одновременно; после закрытия следующий сотрудник может открыть свою.

Ограничения и безопасность
Это MVP-прототип. Без включённой Supabase-синхронизации данные остаются в localStorage браузера. После настройки данные аккаунта передаются в Supabase по HTTPS и становятся доступны на устройствах, вошедших в один аккаунт. PIN — только локальная защита интерфейса для прототипа: он не заменяет серверную авторизацию и может быть обойдён человеком с доступом к устройству и инструментам разработчика браузера. Синхронизация прототипа не заменяет полноценную серверную кассовую систему с транзакциями, авторизацией по ролям и аудитом. Очистка данных браузера может удалить историю — регулярно скачивайте резервную копию. Приложение не является фискальной кассой и не отправляет чеки в налоговую. Для реальной эксплуатации нужны backend, авторизация и права ролей, синхронизация с разрешением конфликтов, шифрование/резервирование и проверка требований законодательства вашей страны.
